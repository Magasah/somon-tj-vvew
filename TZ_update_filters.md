## 1. Цель обновления

Владелец настраивает **через кнопки в Telegram**, какие вакансии ему присылать. Логика как в фильтрах на сайте somon.tj:

| Фильтр | Как выбирается |
|---|---|
| 🗂 Категории | несколько из списка (сейчас в меню видны только 2) |
| 📍 Город | несколько городов или «Все города» |
| 💰 Зарплата, c. | от — до, плюс переключатель «Показывать „Договорная“» |
| 🕒 График | несколько значений или «Любой» |
| 🎓 Стаж | несколько значений или «Любой» |
| 🔤 Ключевые слова | текущие include/exclude (уже есть, переносим в это меню) |

Уведомление приходит **только** если вакансия проходит **все** активные фильтры.

Требования к интерфейсу: удобно, понятно, без спама в чате. Меню редактируется на месте (одно сообщение), а не присылает новое на каждое нажатие.

## 2. Что известно о сайте (проверено 2026-10-06)

### 2.1. Карточка в списке раздела
Содержит: название, зарплату, город, дату. Примеры текста карточек:
- `Модератор - удаленно, выходные дни ...` | `VIP900 c.` | `Худжанд` | `2 недели назад`
- `Менеджер по продажам в раздел General` | `VIPДоговорная` | `Душанбе` | `2 недели назад`
- `Курьер - район Восеъ` | `ТОПДоговорная` | `Восе` | `1 час назад`

Значки `VIP`, `ТОП` и подобные могут быть **склеены** с ценой. Их нужно отделять.

### 2.2. Страница объявления `/adv/<id>_<slug>/`
Содержит поля в виде «метка: значение». Пример (объявление 16556274):
- `График`: `Полный день`
- `Стаж`: `От 3 лет`
- `Город`: `Душанбе`
- `Сфера деятельности компании`: `Финансы`
- `Название, адрес компании`: `ibt.tj`

**График и стаж есть только на странице объявления.** В карточке списка их нет.

### 2.3. Города в фильтре сайта (неполный список)
`Душанбе`, `Худжанд`, `Кӯлоб`, `Бохтар (Курган-Тюбе)`, `Восе`, `Джаббор Расулов` и другие. Полный список собери на шаге 9.1.

### 2.4. Правила сбора (как и раньше, не нарушать)
- **Не используй фильтры сайта через URL.** В `robots.txt` запрещены параметры `attrs__`, `price_min`, `price_max`, `ordering`. Вся фильтрация делается **локально** в боте после парсинга.
- Городские пути вида `/vakansii/<категория>/<город>/` использовать **не нужно**: это умножит число запросов. Опрашиваем только страницу категории, город фильтруем локально.
- Все запросы (списки и страницы объявлений) идут через существующий `fetcher` с задержкой ≥ 3 секунды, строго последовательно.

## 4. Модель данных

### 4.1. Профиль фильтров (`jobbot/filters.py`)

Pydantic-модель `FilterProfile`, хранится в базе одной JSON-строкой с полем версии:

```python
class SalaryFilter(BaseModel):
    min: int | None = None  # «от», сомони
    max: int | None = None  # «до», сомони
    include_negotiable: bool = True  # показывать «Договорная»


class FilterProfile(BaseModel):
    version: int = 1
    categories: list[str] = ["it", "students"]  # ключи из каталога
    cities: list[str] = []  # нормализованные; [] = все города
    salary: SalaryFilter = SalaryFilter()
    schedules: list[str] = []  # нормализованные; [] = любой
    experience: list[str] = []  # нормализованные; [] = любой
    include_unknown_attrs: bool = True  # пропускать, если график/стаж не указаны
```

Валидация: ключи категорий существуют в каталоге; `0 ≤ min ≤ max ≤ 1_000_000`; не больше 30 городов, 15 графиков, 15 вариантов стажа. При невалидных данных в базе — лог-предупреждение и откат к профилю по умолчанию (бот не падает).

### 4.2. Миграция базы → schema_version 2

Перед миграцией код сам делает копию `data/jobbot.db` → `data/backups/jobbot-<UTC-время>.db`.

```sql
ALTER TABLE ads ADD COLUMN salary_min        INTEGER;
ALTER TABLE ads ADD COLUMN salary_max        INTEGER;
ALTER TABLE ads ADD COLUMN salary_negotiable INTEGER NOT NULL DEFAULT 0;
ALTER TABLE ads ADD COLUMN city_norm         TEXT;
ALTER TABLE ads ADD COLUMN schedule          TEXT;     -- исходный текст с сайта
ALTER TABLE ads ADD COLUMN experience        TEXT;
ALTER TABLE ads ADD COLUMN company           TEXT;
ALTER TABLE ads ADD COLUMN sphere            TEXT;
ALTER TABLE ads ADD COLUMN details_status    TEXT NOT NULL DEFAULT 'none';  -- none|pending|ok|failed|skipped
ALTER TABLE ads ADD COLUMN details_attempts  INTEGER NOT NULL DEFAULT 0;
CREATE INDEX IF NOT EXISTS idx_ads_details ON ads(details_status);

CREATE TABLE IF NOT EXISTS filter_profile (
    id    INTEGER PRIMARY KEY CHECK (id = 1),
    data  TEXT NOT NULL            -- JSON FilterProfile
);

CREATE TABLE IF NOT EXISTS attr_values (   -- справочник реально встреченных значений для кнопок
    attr       TEXT NOT NULL CHECK (attr IN ('city', 'schedule', 'experience')),
    value_norm TEXT NOT NULL,
    label      TEXT NOT NULL,             -- как показывать на кнопке
    seen_count INTEGER NOT NULL DEFAULT 1,
    last_seen  TEXT NOT NULL,
    PRIMARY KEY (attr, value_norm)
);
```

Миграция переносит старые настройки: включённые категории из таблицы `categories` → `FilterProfile.categories`. Таблица `keywords` (include/exclude) остаётся как есть.

Миграция идемпотентна: повторный запуск ничего не ломает. Покрыть тестом на копии базы версии 1.

## 5. Парсинг

### 5.1. Нормализация текста (`jobbot/normalize.py`)
Одна функция для городов, графиков, стажа и ключевых слов:
нижний регистр → `ё→е`, `ӣ→и`, `ӯ→у`, `ҳ→х`, `қ→к`, `ғ→г`, `ҷ→ч` → убрать текст в скобках → схлопнуть пробелы и дефисы → обрезать края.

Примеры: `Кӯлоб` → `кулоб`; `Бохтар (Курган-Тюбе)` → `бохтар`; `Полный день` → `полный день`.

Словарь синонимов городов (минимум): `куляб → кулоб`, `курган-тюбе → бохтар`, `ленинабад → худжанд`. Расширяемый, в одном месте.

### 5.2. Зарплата (`parse_salary(text) -> Salary`)
- Убрать значки: `VIP`, `ТОП`, `TOP`, `Срочно` и подобные в начале строки (список в одном месте).
- `900 c.` → min=900, max=900
- `2 000 c.` / `2 000 с.` (латинская и кириллическая «c», неразрывные пробелы) → 2000
- `от 3 000 c.` → min=3000, max=None
- `до 5 000 c.` → min=None, max=5000
- `1 500 - 3 000 c.` / `1 500–3 000` → min=1500, max=3000
- `Договорная` / `Договорная цена` → negotiable=True
- Любой нераспознанный формат → все поля None, предупреждение в лог с исходным текстом (без падения).

Покрыть таблицей тестов, не меньше 15 случаев.

### 5.3. Страница объявления (`parse_detail(html) -> AdDetails`)
Извлекать пары «метка: значение» и сопоставлять по меткам: `График`, `Стаж`, `Город`, `Сфера деятельности компании`, `Название, адрес компании`. Метки сравнивать после нормализации. Незнакомые метки игнорировать. Если поле не найдено → None.

## 6. Логика отбора (двухступенчатая)

Цель — открывать страницы объявлений как можно реже.

**Ступень 1 — по данным карточки (без доп. запросов):**
1. Категория объявления выбрана в профиле.
2. Город: `cities` пусто ИЛИ `city_norm` в `cities`. Город неизвестен → решает `include_unknown_attrs`.
3. Зарплата:
   - `Договорная` → проходит, только если `include_negotiable = True`.
   - Иначе пересечение диапазонов: объявление `[a_min, a_max]` (пустой край = равен другому краю) и фильтр `[f_min, f_max]` (пустой край = без ограничения). Проходит, если `a_max ≥ f_min` и `a_min ≤ f_max`.
   - Зарплата не распознана → решает `include_unknown_attrs`.
4. Ключевые слова include/exclude — как сейчас (по названию).

**Ступень 2 — только если в профиле активен фильтр «График» или «Стаж»:**
5. Объявлению ставится `details_status = 'pending'`.
6. Детальные страницы загружаются в том же цикле, после списков, **не больше `MAX_DETAILS_PER_CYCLE` (по умолчанию 10)**. Остаток — в следующем цикле. Порядок: от самых новых.
7. Проверка `schedules` и `experience` по нормализованным значениям. Значение не указано на сайте → решает `include_unknown_attrs`.
8. Ошибка загрузки → `details_attempts += 1`, повтор в следующем цикле. После 3 неудач → `details_status = 'failed'`, объявление **отправляется** с пометкой «⚠️ график/стаж не проверены» (лучше лишнее уведомление, чем пропущенная вакансия).

Если «График» и «Стаж» не выбраны, детальные страницы не загружаются вообще (`details_status = 'skipped'`).

**Справочник значений:** каждое встреченное значение города, графика и стажа записывается в `attr_values` (`INSERT ... ON CONFLICT DO UPDATE seen_count = seen_count + 1, last_seen = ...`). Из этой таблицы строятся кнопки меню.

**Изменение фильтров действует на новые объявления.** Старые не пересылаются автоматически (см. кнопку «Проверить фильтр» в 7.3).

`[🗂 Категории] [📍 Город]`

Строка «Подходит за последние 7 дней» считается запросом к базе по текущему профилю. Для объявлений без деталей при активных фильтрах графика/стажа учитывай `include_unknown_attrs`.

### 7.3. Экраны

**🗂 Категории** — кнопки только видимых категорий (`VISIBLE_CATEGORIES`), отметка `✅`/`▫️`, мультивыбор. Нельзя снять последнюю категорию: ответ-всплывашка «Нужна хотя бы одна категория». Кнопка `⬅️ Назад`.

**📍 Город** — кнопка `🌍 Все города` и до 12 городов из `attr_values` (сортировка по `seen_count`), по 2 в ряд, отметки `✅`/`▫️`. Если в справочнике пока меньше 6 городов, добавь стартовые: Душанбе, Худжанд, Кулоб, Бохтар, Восе, Истаравшан. Выбор «Все города» очищает список. `⬅️ Назад`.

**💰 Зарплата** — пресеты «от»: `Любая`, `от 1 000`, `от 2 000`, `от 3 000`, `от 5 000`, `от 8 000`. Кнопка `✏️ Ввести вручную` → бот просит ввести текст (FSM aiogram) в форматах `2000`, `от 2000`, `до 5000`, `2000-5000`. На неверный ввод — понятная ошибка с примерами и повтор запроса. `/cancel` или кнопка `✖️ Отмена` выходят из ввода. Переключатель `«Договорная»: показывать ✅ / скрывать ▫️`. `⬅️ Назад`.

**🕒 График** и **🎓 Стаж** — кнопка `Любой` и значения из `attr_values` (то, что реально встречалось на сайте), мультивыбор. Переключатель `Если не указано: показывать ✅ / скрывать ▫️` (это `include_unknown_attrs`, общий для всех фильтров, показывать на обоих экранах). Под списком подсказка: «Значения берутся с сайта. Новые варианты появятся по мере новых вакансий». `⬅️ Назад`.

**🔤 Ключевые слова** — текущие include/exclude списком, кнопки `➕ Добавить нужное слово`, `➖ Добавить стоп-слово`, `🗑 Удалить слово` (кнопки со словами для удаления). Ввод через FSM с прежней валидацией. `⬅️ Назад`.

**🔍 Проверить фильтр** — показывает до 5 последних подходящих вакансий из базы за 7 дней (компактный список с ссылками) и кнопку `📨 Прислать все подходящие за 24 часа` (не больше 20, дайджестом).

**♻️ Сбросить** — подтверждение внутри сообщения: `Да, сбросить` / `Отмена` (без системных диалогов).

**✅ Готово** — сохраняет профиль, меняет сообщение на итоговую сводку «Фильтры сохранены» + сводка.

### 7.4. Правила UX и техники
- Все изменения сохраняются **сразу** при нажатии (не только по «Готово»), чтобы ничего не терялось.
- После каждого нажатия — `callback.answer()` в течение 1 секунды (короткая всплывашка при необходимости: «Сохранено»).
- Редактируй текущее сообщение (`edit_text` / `edit_reply_markup`). Ошибку `message is not modified` молча игнорируй.
- `callback_data` строится через `CallbackData`-фабрику aiogram, длина ≤ 64 байт. Для городов и значений графика/стажа передавай короткий индекс или хеш, а не полный текст.
- Каждый callback **валидируется**: неизвестное действие, несуществующий ключ, чужой chat_id → игнор + лог. Нельзя доверять `callback_data`.
- Защита от гонок: изменения профиля через одну функцию `update_profile(mutator)` под `asyncio.Lock` в одной транзакции (прочитать → изменить → провалидировать → записать). Быстрые двойные нажатия не должны терять изменения.
- Устаревшие меню (старше 24 часов) при нажатии отвечают «Меню устарело, откройте /filters».
- Тексты короткие, на русском, эмодзи только как маркеры разделов.
