## 1. Цель проекта

Личный Telegram-бот, который:

1. Каждые ~5 минут проверяет на сайте **somon.tj** выбранные разделы вакансий.
2. Находит **новые** объявления, которых раньше не видел.
3. Фильтрует их по ключевым словам владельца.
4. **Сразу** присылает их владельцу в Telegram красивой карточкой со ссылкой.

Причина: приложение Somon не присылает уведомления о каждой новой публикации, а хорошие вакансии для студентов разбирают быстро.

Пользователь бота один — владелец. Посторонним бот не отвечает.

## 2. Источник данных и правила сбора (строго)

### 2.1. Разделы по умолчанию

| Ключ | Название | URL |
|---|---|---|
| `it` | IT, телеком, компьютеры | `https://somon.tj/vakansii/it--telekom--kompyuteryi/` |
| `students` | Начало карьеры, студенты | `https://somon.tj/vakansii/nachalo-kareryi--studentyi/` |

Список разделов задаётся в конфиге. Добавление нового раздела = одна строка в конфиге, без правки кода.

### 2.2. Что известно о сайте

- Список объявлений приходит в обычном HTML (серверный рендер), вход в аккаунт не нужен.
- Ссылка на объявление имеет вид `https://somon.tj/adv/16556274_net-backend-developer/`. Число после `/adv/` и до `_` — **уникальный ID объявления**. По нему определяется новизна.
- На странице есть «поднятые» старые объявления с пометкой «Сегодня». Проверка по ID не даёт прислать их повторно.
- Пагинация: `?page=2`, `?page=3`.

### 2.3. Правила вежливого сбора (нарушать нельзя)

- **Без авторизации.** Никаких логинов, паролей, cookies аккаунта.
- **Не обращаться** к путям, закрытым в `https://somon.tj/robots.txt`: `/api`, `/admin`, `/profile`, `/saved_search/`, `/mobile_search/`, а также к URL с параметрами `ordering`, `price_min`, `price_max`, `attrs__`. Используй только чистые URL разделов и `?page=N`.
- Перед первым запуском и раз в сутки загружай `robots.txt` и проверяй разрешение через `urllib.robotparser`. Если URL раздела запрещён, не запрашивай его и сообщи владельцу.
- Не больше **1 запроса в 3 секунды**, строго последовательно, без параллельных запросов к сайту.
- Интервал опроса — 5 минут плюс случайный джиттер ±60 секунд. Минимально допустимый интервал — 3 минуты (проверяй при загрузке конфига).
- Честный `User-Agent`: `SomonJobAlertBot/1.0 (personal use)`.
- Никакого обхода капчи, ротации прокси или маскировки под браузер.
- На HTTP 403 или 429 — пауза 30 минут и одно уведомление владельцу (не спамить на каждой попытке).

### 2.4. Сколько страниц смотреть

За один цикл по каждому разделу смотри страницу 1. Если **все** объявления на странице 1 новые, смотри следующую страницу, но не дальше страницы 3. Так не теряются вакансии, если бот долго был выключен.

## 3. Функциональные требования

### 3.1. Данные объявления

Из карточки в списке извлекай (если поле есть в разметке):

| Поле | Тип | Обязательно |
|---|---|---|
| `ad_id` | int | да |
| `url` | str (абсолютный, только домен `somon.tj`) | да |
| `title` | str | да |
| `salary_text` | str или None | нет |
| `city` | str или None | нет |
| `date_label` | str или None («Сегодня», «Вчера», дата) | нет |
| `category_key` | str (`it`, `students`) | да |

Загружать страницу самого объявления не нужно (лишние запросы). Это только опция `FETCH_DETAILS=false` на будущее, по умолчанию выключена.

### 3.2. Первый запуск без спама

При первом опросе раздела (в базе нет ни одного объявления этой категории) **сохрани все текущие объявления как уже просмотренные и не отправляй их**. Отправь только последние `SEED_SEND_LAST` (по умолчанию 3) с заголовком «Последние вакансии в разделе …», чтобы владелец увидел, что бот работает.

### 3.3. Фильтры

- Текст для сравнения: `title` (и описание, если когда-нибудь включат `FETCH_DETAILS`).
- Нормализация: нижний регистр, `ё` → `е`, лишние пробелы схлопнуть.
- **include** — список слов. Если для раздела включён режим `keywords`, объявление проходит, только когда содержит хотя бы одно слово из include.
- **exclude** — список слов. Объявление со словом из exclude не отправляется никогда.
- Режим на каждый раздел: `all` (все, кроме exclude) или `keywords` (только по include, кроме exclude).
- Значения по умолчанию:
  - `it` → режим `all`;
  - `students` → режим `all`;
  - include по умолчанию: `python, frontend, backend, разработчик, программист, developer, junior, стажер, стажировка, без опыта, web, react, django, fastapi, 1с, it`;
  - exclude по умолчанию: `колл-центр, колл центр, call center, оператор колл`.
- Объявления, которые не прошли фильтр, тоже сохраняются в базу (с `matched=0`), чтобы не проверять их снова.

### 3.4. Сообщение в Telegram

Формат — `parse_mode=HTML`. **Все данные с сайта экранируются через `html.escape`.**

```
💼 <b>.NET Backend разработчик</b>
💰 5 000 с. · 📍 Душанбе · 🕒 Сегодня
🏷 IT, телеком, компьютеры
```

Под сообщением инлайн-кнопка **«Открыть на Somon»** со ссылкой на объявление.

- Если за один цикл больше 8 новых подходящих объявлений, отправь одно сообщение-дайджест: «Найдено N новых вакансий» и список строк вида «• название — ссылка». Учитывай лимит Telegram в 4096 символов: при превышении дели на несколько сообщений.
- Между сообщениями пауза не меньше 1 секунды. На `TelegramRetryAfter` жди указанное время и повторяй.

### 3.5. Команды бота

Бот реагирует **только** на `OWNER_CHAT_ID`. Сообщения от остальных молча игнорирует (без ответа) и пишет в лог предупреждение.

| Команда | Что делает |
|---|---|
| `/start` | Приветствие и краткая справка |
| `/help` | Список команд |
| `/status` | Время последнего опроса, сколько объявлений в базе, сколько отправлено за сегодня, пауза вкл/выкл, последние ошибки |
| `/check` | Опросить сайт прямо сейчас (не чаще раза в минуту) |
| `/pause` / `/resume` | Остановить или возобновить уведомления (опрос продолжается, новые объявления копятся) |
| `/filters` | Показать include и exclude и режимы разделов |
| `/include <слово>` | Добавить слово в include |
| `/exclude <слово>` | Добавить слово в exclude |
| `/remove <слово>` | Удалить слово из обоих списков |
| `/categories` | Инлайн-кнопки: включить или выключить раздел, переключить режим `all`/`keywords` |
| `/last [n]` | Прислать последние n (1–20, по умолчанию 5) подходящих вакансий из базы |

Валидация ввода: слово от 2 до 40 символов, только буквы, цифры, пробел, `-`, `+`, `#`, `.`. Не больше 100 слов в каждом списке. При ошибке — понятный ответ, что не так и как исправить.

После `/resume` отправь объявления, накопленные за паузу (дайджестом, если их больше 8).

### 3.6. Самодиагностика

- Если в разделе распарсилось **0 объявлений** три цикла подряд, отправь владельцу: «⚠️ Парсер раздела … не нашёл объявлений 3 раза подряд. Возможно, сайт изменил вёрстку». Повторно напоминай не чаще раза в 6 часов.
- Если основной парсер нашёл 0 карточек, но на странице есть ссылки `/adv/\d+_`, используй **запасной парсер**: извлеки ID и текст ссылки регулярным выражением. Уведомление с запасного парсера помечай «(упрощённый режим)».
- После 5 сетевых ошибок подряд — одно уведомление владельцу. После восстановления — сообщение «✅ Связь с сайтом восстановлена».

## 4. Нефункциональные требования

### 4.1. Безопасность (OWASP-мышление)

- Секреты (`BOT_TOKEN`, `OWNER_CHAT_ID`) — только в `.env`. В репозитории лежит `.env.example` с пустыми значениями. `.env` в `.gitignore`.
- Токен никогда не попадает в логи, исключения и сообщения. Настрой фильтр логов, который маскирует строки, похожие на токен (`\d+:[A-Za-z0-9_-]{35}`).
- Доступ к боту — только `OWNER_CHAT_ID` (middleware aiogram, проверка до любого хендлера).
- Всё, что пришло с сайта, — недоверенные данные: экранирование в HTML-сообщениях, проверка, что `url` начинается с `https://somon.tj/adv/`, ограничение длины полей (title до 300 символов).
- SQL — только параметризованные запросы, никакой сборки SQL строками.
- Контейнер запускается от непривилегированного пользователя.
- Зависимости зафиксированы по версиям в `requirements.txt` (или `pyproject.toml` + lock).

### 4.2. Корректность и защита от гонок

- Один фоновый цикл опроса на весь процесс. `/check` не запускает второй параллельный опрос: используй `asyncio.Lock`. Если опрос уже идёт, ответь «Проверка уже идёт».
- Сохранение и отправка устроены так, чтобы не было ни дублей, ни потерь:
  1. В одной транзакции `INSERT OR IGNORE` объявления с `sent_at = NULL`. Если строка уже была, объявление не новое, дальше не идём.
  2. Отправка в Telegram.
  3. Только после успешной отправки — `UPDATE ads SET sent_at = now WHERE ad_id = ?`.
  4. При старте бот досылает подходящие объявления с `sent_at IS NULL`, найденные не раньше чем 24 часа назад.
- SQLite в режиме WAL, `busy_timeout = 5000`. Одно подключение на процесс через aiosqlite.
- Graceful shutdown по SIGTERM/SIGINT: дождаться конца текущего цикла (до 30 секунд), закрыть HTTP-клиент, базу и сессию бота.

### 4.3. Скорость и ресурсы

- Один переиспользуемый `httpx.AsyncClient` (keep-alive, `timeout=15s`, `follow_redirects=True`).
- Парсинг на `selectolax` (быстрее BeautifulSoup). Если `selectolax` по какой-то причине не подходит, запиши в «Решения» почему и используй `BeautifulSoup` + `lxml`.
- Память в простое — до 80 МБ. Один цикл (2 раздела) — до 10 секунд без учёта пауз между запросами.
- Индексы в базе: по `category_key` и `first_seen_at`.

### 4.4. Надёжность сети

- Повторы: 3 попытки с задержками 2, 4 и 8 секунд плюс случайный джиттер. Только на таймауты, сетевые ошибки и 5xx.
- 403/429 — без повторов, сразу пауза 30 минут (раздел 2.3).
- Ошибка в одном разделе не останавливает опрос остальных.
- Любое исключение в цикле логируется со стеком, а цикл продолжает работать.

### 4.5. Удобство

- Запуск одной командой (локально и в Docker).
- Режим отладки: `python -m jobbot --once --dry-run` — один опрос, вывод найденных новых объявлений в консоль, без записи в базу и без отправки.
- Логи читаемые, с временем по `Asia/Dushanbe`: `2026-10-05 19:05:12 | INFO | poller | it: найдено 20, новых 2, отправлено 1`.
- Понятный `README.md` на русском: как получить токен у @BotFather, как узнать свой chat_id, как запустить, как обновить.

## 7. Схема базы данных

```sql
CREATE TABLE IF NOT EXISTS schema_version (version INTEGER NOT NULL);

CREATE TABLE IF NOT EXISTS ads (
    ad_id         INTEGER PRIMARY KEY,          -- ID из URL
    category_key  TEXT    NOT NULL,
    title         TEXT    NOT NULL,
    url           TEXT    NOT NULL,
    salary_text   TEXT,
    city          TEXT,
    date_label    TEXT,
    matched       INTEGER NOT NULL DEFAULT 0,   -- прошло фильтр
    first_seen_at TEXT    NOT NULL,             -- ISO 8601 UTC
    sent_at       TEXT                          -- NULL = ещё не отправлено
);
CREATE INDEX IF NOT EXISTS idx_ads_category ON ads(category_key);
CREATE INDEX IF NOT EXISTS idx_ads_seen     ON ads(first_seen_at);

CREATE TABLE IF NOT EXISTS keywords (
    kind    TEXT NOT NULL CHECK (kind IN ('include', 'exclude')),
    word    TEXT NOT NULL,
    PRIMARY KEY (kind, word)
);

CREATE TABLE IF NOT EXISTS categories (
    key      TEXT PRIMARY KEY,
    enabled  INTEGER NOT NULL DEFAULT 1,
    mode     TEXT NOT NULL DEFAULT 'all' CHECK (mode IN ('all', 'keywords'))
);

CREATE TABLE IF NOT EXISTS state (
    key   TEXT PRIMARY KEY,
    value TEXT NOT NULL
);  -- paused, last_poll_at, empty_streak:<cat>, last_alert_at:<type>
```

Миграции: при старте читай `schema_version` и применяй недостающие шаги по порядку.

## 9. Этапы и критерии приёмки

### Этап 0. Каркас
